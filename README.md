# 선상24 낚시배 모니터링 (GitHub Actions + 텔레그램)

선상24에서 조건에 맞는 낚시배가 새로 나타나면 텔레그램으로 알려줍니다.
GitHub 클라우드에서 5분마다 자동 실행되므로 PC를 켜둘 필요가 없습니다.
텔레그램 그룹에서 명령어로 설정을 바꾸거나 현재 상태를 조회할 수도 있습니다.

## 텔레그램 명령어

그룹 채팅에 아래 명령을 보내면 됩니다. 5분마다 실행되므로 응답까지
최대 5~15분 걸릴 수 있습니다.

| 명령 | 설명 |
|---|---|
| `/help` | 명령어 목록 |
| `/status` | 현재 설정 + 지금 조건에 맞는 배 보기 |
| `/all` | 조건 무시하고 자리 있는 배 전부 보기 (동작 확인용) |
| `/history` | 최근 조회 이력 (언제 몇 건 잡혔는지) |
| `/date 2026-09-26,2026-09-27` | 감시 날짜 변경 |
| `/seats 2` | 최소 인원 변경 |
| `/hours 12 19` | 출항 시간대 변경 (12시~19시 출항) |
| `/board 10` | 최소 조황정보 건수 변경 |

## 파일 구성

| 파일 | 역할 |
|---|---|
| `monitor_sunsang24.py` | 본체 스크립트 |
| `.github/workflows/monitor.yml` | 5분마다 실행하는 설정 |
| `config.json` | 감시 조건 (명령어로 자동 변경됨) |
| `seen_schedules.json` | 이미 알림 보낸 배 기록 (중복 알림 방지) |
| `history.json` | 조회 이력 (최근 30회) |
| `tg_offset.json` | 텔레그램 메시지를 어디까지 읽었는지 표시 |

`config.json` 은 텔레그램 명령으로 바뀌므로 직접 수정할 필요는 없지만,
GitHub 웹에서 직접 고쳐도 됩니다.

## 설정 방법 (최초 1회)

1. GitHub에 새 저장소를 만들고 이 폴더의 파일을 전부 업로드합니다.
   (`.github/workflows/monitor.yml` 은 숨김 폴더라 드래그가 안 되니,
   저장소에서 `Add file > Create new file` 을 누르고 파일명 칸에
   `.github/workflows/monitor.yml` 을 그대로 입력해서 만드세요.)
2. Settings > Secrets and variables > Actions 에서 아래 두 개를 등록합니다.
   - `TELEGRAM_BOT_TOKEN` : BotFather에서 받은 봇 토큰
   - `TELEGRAM_CHAT_ID` : 알림받을 그룹의 chat_id
3. Actions 탭 > 왼쪽에서 워크플로우 선택 > `Run workflow` 로 한 번 실행해
   정상 동작을 확인합니다.

## 명령어 권한 제한 (선택)

기본값은 그룹의 누구나 명령을 쓸 수 있습니다. 특정 사용자만 허용하려면
`monitor_sunsang24.py` 의 `ALLOWED_USER_IDS` 에 본인 텔레그램 사용자 ID를
넣으세요. 예: `ALLOWED_USER_IDS = [123456789]`
(ID는 그룹에 메시지를 보낸 뒤 getUpdates 응답의 `"from":{"id":...}` 에서 확인)

## 참고 / 한계

- GitHub의 예약 실행은 서버 상황에 따라 몇 분 지연될 수 있습니다.
- 저장소에 60일 이상 활동이 없으면 예약 실행이 자동 비활성화됩니다.
  이 워크플로우는 상태 파일을 계속 커밋하므로 해당될 가능성은 낮습니다.
- 이미 알림을 보낸 배는 다시 알리지 않습니다. 그 배의 남은 자리 수가
  나중에 늘어나도 재알림하지 않습니다.
- 낚시 일정이 끝나면 Settings > Actions 에서 워크플로우를 꺼두세요.
