# 낚시배 빈자리 알림봇 v2 (다인 사용)

선상24 · 더피싱 · 클럽씨피싱(홍성 남당항)의 빈자리를 감시해 텔레그램 1:1 대화로 알려줍니다.
관리자 승인을 받은 최대 10명이 각자 다른 날짜·어종·지역·인원으로 감시할 수 있습니다.

## 구조

- 실행: cron-job.org 가 10분마다 GitHub Actions 를 실행 (GitHub 자체 예약 실행은 사용 안 함)
- 저장: 사용자·감시 목록·알림 기록을 **암호화해서** `state.enc` 하나에 저장
- 대화: 그룹방이 아니라 **각자 봇과 1:1 대화** (그룹방 메시지는 무시)

## 파일

| 파일 | 역할 |
|---|---|
| `monitor_sunsang24.py` | 본체 |
| `.github/workflows/monitor.yml` | 실행 설정 |
| `state.enc` | 암호화된 상태 (첫 실행 때 자동 생성) |

## v1 에서 옮기기 (1회)

1. **Secrets 추가** (Settings > Secrets and variables > Actions)
   - `ADMIN_USER_ID` : 본인 텔레그램 사용자 ID (숫자). 확인법은 아래 참고
   - `STATE_KEY` : 암호화 비밀번호. Mac 터미널에서 `openssl rand -base64 32` 결과를 그대로 사용
   - `TELEGRAM_BOT_TOKEN` 은 그대로 사용, `TELEGRAM_CHAT_ID` 는 더 이상 안 씀 (삭제 가능)
2. `monitor_sunsang24.py`, `.github/workflows/monitor.yml` 을 새 파일로 **전체 교체**
3. Actions 탭 > sunsang24-monitor > Run workflow 로 1회 실행
   - 기존 `config.json` 의 날짜·조건이 관리자 감시 #1 로 자동 이관됩니다
   - 이관 직후에는 현재 빈자리가 한 번 알림으로 옵니다
4. 정상 동작 확인 후 `config.json`, `seen_schedules.json`, `history.json`, `tg_offset.json` 삭제
5. cron-job.org 주기는 10분 유지

### 본인 사용자 ID 확인
봇과의 1:1 대화창에서 아무 메시지나 보낸 뒤, 브라우저에서
`https://api.telegram.org/bot<봇토큰>/getUpdates` 를 열어 `"from":{"id":숫자` 의 숫자를 확인합니다.

### STATE_KEY 주의
- 잊어버리면 상태를 복구할 수 없습니다 (사용자 전원 재가입 필요). 비밀번호 관리 앱 등에 보관하세요.
- 키가 틀리면 스크립트는 상태를 **덮어쓰지 않고 중단**하며 관리자에게 알립니다.

## 다른 사람 초대

1. 봇 주소(`https://t.me/봇사용자명`)를 전달
2. 상대가 봇 대화창에서 `/join`
3. 관리자에게 온 메시지의 `/approve_ID` 를 누르면 승인

## 명령어

**사용자**

| 명령 | 설명 |
|---|---|
| `/add 2026-10-03 주꾸미 충남,경기 2` | 감시 추가 (최대 3개) |
| | 날짜 여러 개 `2026-10-03,2026-10-04` / 기간 `2026-10-03~2026-10-05` (최대 7일) |
| `/list` · `/del 번호` | 내 감시 목록 · 삭제 |
| `/status` | 내 조건으로 지금 바로 조회 |
| `/pause` · `/resume` | 내 알림 일시정지 · 재개 |
| `/hours 12 19` · `/board 10` | 선상24 출항시간 범위 · 최소 조황정보 건수 |
| `/fish` · `/regions` | 지원 어종 · 지역 |
| `/history` · `/ping` | 최근 실행 기록 · 동작 확인 |
| `/leave` | 탈퇴 |

**관리자 추가 명령**

| 명령 | 설명 |
|---|---|
| `/users` | 사용자 목록 |
| `/approve ID` · `/reject ID` · `/kick ID` | 승인 · 거절 · 삭제 |
| `/pauseall` · `/resumeall` | 사이트 조회 전체 정지 · 재개 (명령 처리는 계속) |
| `/health` | 사이트별 상태 |
| `/notice 내용` | 전체 공지 |

응답은 다음 실행 때 나가므로 최대 10분 걸립니다.

## 알림 규칙

- **"자리 없음 → 있음"으로 바뀔 때마다** 알립니다. 매진됐다가 취소로 다시 열려도 다시 알림
- 사이트 조회가 실패한 동안에는 이전 상태를 유지 → 복구됐을 때 가짜 재알림 없음
- 날짜가 모두 지난 감시는 자동 삭제 후 본인에게 안내
- 한 사이트가 3회 연속 조회 실패하면 관리자에게 경고, 복구되면 다시 알림
- 같은 조건을 여러 명이 감시해도 사이트에는 한 번만 요청

## 사이트별 적용 범위

| 조건 | 선상24 | 더피싱 | 클럽씨피싱 |
|---|---|---|---|
| 날짜·어종 | O | O | O (공지 문구로 판단) |
| 지역 | O | O | 충남·홍성 포함 시에만 조회 |
| 인원 | O | X (잔여석 미공개) | O |
| 출항시간·조황정보 | O | X | X |
| 예약 링크 | 예약 화면 직행 | 검색 결과 페이지 | 그 날짜 목록 |

- 선상24 지역표는 실행 때마다 사이트에서 받아옵니다. 선상24에서는 '경기'에 인천이 포함되지 않습니다.
- 주꾸미·갑오징어는 더피싱의 '쭈갑' 출조도 함께 조회합니다.

## 공개 저장소 관련 참고

- `state.enc` 는 Fernet(AES-128 + HMAC-SHA256)으로 암호화되며, 키는 비밀번호(STATE_KEY)에서
  PBKDF2-SHA256 20만 회로 만듭니다. 안전성은 STATE_KEY 의 길이·무작위성에 달려 있으므로
  위의 `openssl rand` 방식처럼 긴 무작위 값을 쓰세요.
- 공개 저장소는 **Actions 실행 로그도 누구나 볼 수 있습니다.** 스크립트는 로그에 건수와
  오류 종류만 남기고 이름·ID·감시 조건은 출력하지 않습니다. 코드를 고칠 때도 이 원칙을 지키세요.
- 클럽씨피싱 화면의 예약자 실명은 수집하지 않습니다.
- 매 실행마다 실행 기록이 바뀌므로 `state.enc` 커밋이 10분마다 쌓입니다.
